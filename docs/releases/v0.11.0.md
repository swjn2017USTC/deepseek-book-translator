# v0.11.0

## EPUB canonical Markdown pipeline

v0.11 changes the default architecture for **new EPUB projects**. EPUB is now treated as an input container, normalized locally into the same reviewed-source/canonical-segment representation used by OCR books, translated through the shared contextual micro-batch pipeline, and rebuilt as a clean standardized EPUB3.

Existing projects explicitly created with `epub_native_v1` remain supported for resume compatibility. New projects use `epub_markdown_v2`.

### Why

Real-world EPUBs vary widely in OCF packaging, OPF metadata, XHTML correctness, CSS conventions, inline markup, attributes, links, footnote implementations and publisher-specific structure. Preserving arbitrary source DOM while translating caused source-specific parser work and leaked formatting details into translation prompts.

v0.11 moves those differences to one local import boundary:

```text
source EPUB
  -> archive safety checks
  -> tolerant OPF / spine discovery
  -> tolerant HTML semantic extraction
  -> canonical segments + local assets
  -> source_review.md
  -> optional human review
  -> shared glossary + contextual micro-batch translation
  -> book_translated.md
  -> Pandoc EPUB3 rebuild + EPUBCheck
```

## Tolerant EPUB import

The new importer:
- keeps path traversal, path collision, archive size and compression-ratio safety limits;
- does not require the source `mimetype` member to be first and uncompressed merely to extract a readable book;
- tolerates common HTML-ish/non-XML-perfect content documents;
- discovers the OPF from `container.xml` with a deterministic `.opf` fallback;
- uses spine order as reading order;
- extracts standard headings, paragraphs, list items, blockquotes, captions, definitions, footnotes and table-cell text;
- recognizes common publisher CSS/id heading hints such as chapter/section-title classes;
- falls back to loose body text when semantic block markup is poor;
- excludes scripts/styles/code/math from ordinary prose extraction;
- reports warnings rather than teaching the translation model source-package quirks.

If an EPUB contains no extractable text, the workflow fails clearly and should switch to OCR.

## Reviewed source

EPUB and OCR now share the same reviewed-source gate.

For EPUB, `source_review.md` marks source spine locations such as:

```text
[EPUB source: OPS/Text/ch03.xhtml]
```

It contains no `[[EPUB:...]]` protected DOM tokens in the new adapter. Stable hidden `BOOK_SEGMENT` markers still make human edits round-trippable.

## Images and cover

Local body images are extracted into:

```text
assets/epub/
```

They are represented as normal Markdown images and carried into the rebuilt EPUB.

Cover policy:
1. prefer EPUB3 `cover-image`;
2. then EPUB2 `meta name="cover"`;
3. then guide / cover filename heuristics;
4. reuse a source JPEG/PNG cover and register provenance;
5. if no reusable cover exists, automatically generate the existing local typographic cover.

The source cover is not replaced simply to standardize the rest of the book.

## Translation

After source approval, EPUB uses the same v0.10 translation path as OCR:
- automatic terminology review;
- thinking disabled by default;
- contextual micro-batches up to 4 ordinary consecutive targets / 6000 source characters;
- high-risk items can remain singleton;
- partial valid output salvage;
- recursive fallback only for unresolved targets;
- chapter-lane parallelism;
- cost/cache/retry telemetry.

Source EPUB DOM/CSS never needs to enter the translation prompt.

## Publication

`epub_markdown_v2` uses the generic publisher:

```bash
python3 new_book.py render --project <PROJECT_DIR>
python3 new_book.py export --project <PROJECT_DIR> --format epub
```

Pandoc rebuilds a clean EPUB3 from canonical translated Markdown, registered cover and extracted local images. EPUBCheck remains the formal delivery gate.

### Intentional tradeoff

v0.11 does **not** promise pixel/DOM-identical preservation of arbitrary source:
- CSS;
- fonts;
- scripts;
- complex interactive behavior;
- publisher-specific DOM;
- every unusual link/footnote implementation.

The invariant is instead a reviewable reading-order text/heading/image representation and a stable standardized output pipeline.

## Windows / Skill / Coding Agent

- Windows GUI treats only OCR projects as Vision candidates; EPUB normalization is local and does not spend Vision tokens.
- The frozen offline smoke now validates both OCR/Vision translation flow and deliberately noncanonical EPUB -> canonical Markdown import with source-cover reuse.
- The Skill and Coding Agent instructions explicitly prohibit source-specific EPUB prompt hacks: diagnose/fix the importer or use OCR instead.
- Existing `epub_native_v1` projects may resume, but new projects do not select it.
