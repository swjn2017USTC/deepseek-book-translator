# v0.9.0

## Highlights

v0.9.0 upgrades OCR/PDF chapter recovery into an auditable multimodal evidence-fusion pipeline while keeping the existing deterministic tree builder and human structure gate.

### DeepSeek Vision structure recovery

- New CLI:
  `python3 new_book.py vision-structure --project <PROJECT_DIR> [--pdf <SOURCE.pdf>]`
- Uses the same `DEEPSEEK_API_KEY`; Vision model can be overridden independently with `DEEPSEEK_VISION_MODEL`.
- Default Vision model: `deepseek-flash`, thinking disabled, bounded JSON output.
- Finds real table-of-contents pages visually, transcribes visible TOC entries/page labels, and preserves TOC indentation depth.
- Uses TOC page labels plus the existing page map to strengthen body-page localization.
- Searches for secondary/tertiary headings omitted from the printed TOC.
- Default body scanning is bounded: candidate pages are selected from PaddleOCR title labels, numbering, short-title geometry, PyMuPDF large-font evidence and TOC target pages.
- Optional `vision.scan_all_body_pages=true` enables higher-recall, higher-cost full-body scanning.

### Evidence fusion and safety

- Vision results are stored in `structure/vision_structure.json`, including model, source hashes, scanned pages, TOC rows, headings and token usage.
- Sidecars are bound to OCR JSON SHA-256 and, when available, PDF SHA-256; stale evidence is rejected.
- Explicit numbering remains higher priority than Vision hierarchy.
- Vision headings that match same-page OCR text become strong evidence without rewriting the OCR source title.
- Vision-only headings with no OCR text match remain below the normal automatic-accept threshold and are sent to the human structure review gate.
- Remote OCR image URLs are ignored by default; local images, data URLs and PDF renders are preferred. Remote image use requires explicit opt-in.

### Existing tools reused

- PaddleOCR / PP-DocLayout labels such as `doc_title`, `paragraph_title` and `table of contents`.
- Existing global monotone TOC-to-body alignment, page-map inference, numbering grammar, style inference and validation.
- PyMuPDF bookmarks/font evidence, now also used for page rendering.
- A Docling-like evidence priority (bookmarks → numbering → visual style) is adopted without bundling the full Docling stack.

### Windows GUI

Normal OCR workflow is now:

1. offline deterministic prepare;
2. automatic DeepSeek Vision structure enhancement;
3. human chapter review only when ambiguity remains;
4. automatic LLM glossary review;
5. translation.

The GUI includes an optional **Vision PDF** selector. If omitted, the workflow searches for a same-stem PDF and then local/data-URL OCR page images.

PyMuPDF is bundled in the Windows executable and verified by both the GUI self-test and the frozen offline smoke.

### Native EPUB

Native EPUB remains on its package/DOM-preserving path and does not use OCR/PDF Vision chapter recovery.
