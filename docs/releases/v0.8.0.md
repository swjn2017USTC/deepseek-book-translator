# v0.8.0

## Highlights

- Windows GUI now accepts either PaddleOCR JSON or native reflowable EPUB from the same file picker.
- Native EPUB stays on the package/DOM-preserving path and preserves its embedded cover and opaque resources.
- Chapter/structure recognition remains the normal human review gate.
- Terminology review is automatic by default after the structure gate:
  - DeepSeek decides every generated candidate as include or reject.
  - Included terms receive a book-level target-language translation.
  - Low-confidence first-pass decisions receive a second LLM adjudication pass.
  - Decisions, source evidence references, confidence, model identity and token usage are retained in auditable files.
- New CLI command: `new_book.py auto-glossary --project <PROJECT_DIR>`.
- The installable `deepseek-book-translation` Skill, Coding Agent instructions and Windows workflow are aligned with the same policy.
- Frozen Windows offline smoke now verifies that the automatic terminology path is exercised.
- Package version: `0.8.0`.

## Windows workflow

Normal OCR workflow:

1. Select JSON and initialize.
2. Prepare.
3. If chapter review is required, review and compile it manually.
4. The next prepare step automatically runs DeepSeek terminology review.
5. Preflight, translate, render and export.

Normal EPUB workflow:

1. Select EPUB and initialize.
2. Prepare; compatibility is checked without OCR/Pandoc reconstruction.
3. Automatic terminology review runs when candidates exist.
4. Preflight and translate.
5. Render/export writes the translated EPUB while retaining the source package structure.

The API key remains in process memory/environment only and is not written into the book project.
